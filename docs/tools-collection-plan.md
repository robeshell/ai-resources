# 工具模块重新收录计划

2026-09-08：按用户要求清空旧版 38 条工具，重新规划少量收录。内容库与公开 tools.json 均已清空，其他板块保留。旧数据备份保存在本机 `.curator/backups/`，不作为当前收录名单。

## 定位

面向用 AI 完成日常工作与创作的人，收录少量能直接使用、有清晰用途的产品。读者应能快速判断：这个工具解决什么任务、何时选它、从哪里开始。

首批目标约 8 个。下面是候选名额分配，不是必须填满的分类配额，也不代表已确定具体产品。

| 任务 | 首批名额 | 选择依据 |
| --- | --- | --- |
| 日常问答、写作与文件处理 | 2 | 使用场景或工作方式有明确差异 |
| 编写与修改代码 | 2 | 覆盖不同使用方式，避免同质编码 Agent 堆叠 |
| 生成与编辑图片 | 1 | 具体创作流程清楚，有直接使用入口 |
| 生成与处理视频 | 1 | 核心视频任务清楚，上手条件可核实 |
| 查资料与整理来源 | 1 | 与通用助手相比有明确任务价值 |
| 音乐或配音 | 1 | 先选择一个明确需求，不为覆盖音频子类增加数量 |

自动化平台、开发者 API、模型厂商和模型本体暂不进入首批。以后出现明确需求再讨论；不自动搬到其他板块凑数。

## 入选条件

1. 以具体可用产品为收录单位，名称与实际入口对应。
2. 能讲清一个典型任务，以及相对已收录工具的具体差异；不以知名度作为唯一理由。
3. 官网或官方文档能验证用途、可用入口与关键使用条件。
4. 没有独立价值的同类候选不录入。证据不足的候选留在待核验名单，不直接发布。
5. 新增工具前检查是否能替换已有条目，避免名单持续膨胀。超过首批规模时重新评估范围。

## 每条内容

- 一句定位：具体用途或可核实的差异，不用口号和无依据的效果承诺。
- 短摘要：用户带着什么任务来，能得到什么结果。
- 详情：实际工作方式、适用场景和一个决定是否使用的关键限制；不重复前两层。
- 分类：按主要用途只选一个，不能因附带功能改变归类。
- 属性：收费方式和平台分别核实；未知不猜测，缺失不等于不支持。
- 核验记录：保存官方依据链接、核验日期与尚未确认的事项。编辑更新时间不代替核验日期。

## 执行顺序

1. 确定首批候选及各自入选理由，不从旧名单自动恢复。
2. 逐个查阅官方资料，核实当前可用性、入口和使用条件。
3. 写成结构化草稿，对同类条目检查差异与重复。
4. 通过内容库保存并导出公开数据；核对最终数量、分类与展示内容。
