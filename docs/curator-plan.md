# Curator 管理台

本地编辑后台。公开站只读仓库里的 JSON；增删改、归档、收录和预览都从这里走。

服务只监听 `127.0.0.1`。静态部署会去掉 `out/curator/`。没有账号、没有数据库。

## 它管什么

| 对象 | 文件 | 能做什么 |
|------|------|----------|
| 资源 | `tools.json` / `resources.json` | 列表、筛选、编辑、归档、恢复 |
| 收录 | 同上，经分析草稿 | 粘贴链接，Agent 出草稿，确认入库 |
| 模型清单 | `model-inbox.json` | 查看、丢掉；不写入本站公开目录 |
| 场景方案 | `scenarios.json` | 编辑标题、说明、关联资源 |
| 站点 | `site.json` | 评测站地址；更新日期随保存自动写 |

分类 taxonomy 固定 6 个场景，管理台不提供新建分类。

Agent（Codex / Claude Code + 模型）是收录步骤的工具，不是管理系统本身。

## 页面

| 路径 | 职责 |
|------|------|
| `/curator/` | 总览：数量、归档、清单、最近更新 |
| `/curator/resources/` | 资源库：筛选列表 + 编辑 |
| `/curator/ingest/` | 收录一条 |
| `/curator/inbox/` | 模型待转移 |
| `/curator/scenarios/` | 场景方案 |
| `/curator/settings/` | 站点设置 |

顶栏常驻：连接状态、生成预览。

资源编辑不用动态路由。静态导出下新条目没有预生成 `[slug]` 页；用同一页按选中项编辑。

## 工作流

1. 收录：链接 → 本机 Agent → 人工改文案 → 写入 JSON。
2. 维护：在资源库改 verdict / 分类 / 关联，或归档下架。
3. 预览：生成预览，打开 `/zh/` 看公开站。
4. 发布：git 提交后由 Pages 工作流构建。线上仍然没有 Curator。
